# Product workflow QA — October 11, 2026

## Scope

Computer-use QA against a fresh local checkout of `fil-one/clockwork`, starting
from `f355d26c`, on branch `codex/ux-workflow-qa`. The Next.js development
server ran with the explicit demo and evidence adapters at
`http://127.0.0.1:3000`. All created orders, quotes and payments used fictional,
resettable records. No hosted deployment, live payment, provider call, email or
production account was involved.

The browser was exercised at its desktop size and at 390 × 844 for the partner
quote detail and revised-quote picker. Phone-width pages measured 390 pixels
wide with no horizontal document overflow.

## Findings implemented

1. **Quote selection was difficult to discover and operate.** Customer and
   partner offer fields relied on native datalists. Clicking or pressing Down
   exposed no selectable choices in the test browser, leaving users to guess the
   exact offer label. The customer account/offer and partner offer/end-client
   fields now use an explicit, labeled listbox. Focus reveals available choices;
   typing searches labels and descriptions; arrows and Enter select without
   submitting the form; Escape and Tab dismiss it; empty searches report no
   results. Existing account and offer validation remains in place.
2. **Order preparation looked like binding acceptance.** The first action read
   “Accept order and create commitment,” even though it only requested an order
   form. It now reads “Prepare order form for review,” with a preparation state
   while the document is pending. The pending explanation explicitly says that
   review and confirmation are still required. The final create action remains
   separate. Copy is supplied in all eight supported interface languages.
3. **Page announcements described loading placeholders as completed pages.**
   Client transitions sometimes announced “Loading records. Page loaded.” The
   shell now waits for loading boundaries to resolve before naming the actual
   destination. Loading regions expose `aria-busy`. A normal online page load no
   longer announces “Connection restored”; real connectivity events still do.
4. **Wrapped links had incomplete click targets.** Center-clicking a wrapped
   invoice name did not open it; keyboard activation did. Record links now have
   a continuous rectangular target. The partner draft success link has the same
   treatment and an underline, so it is distinguishable from the surrounding
   success text.

## Remaining limits

This is a focused local UX pass, not production qualification or exhaustive
coverage of every staff capability. The hosted service was not changed.

Historical demo dates remain inconsistent: the renewal still displays an August
expiry while its acceptance fixture rolls that expiry forward, and some partner
and overdue-invoice summaries still use the July seed clock. Correcting this
requires coordinating the fixture clock, projections and immutable sample PDFs;
changing only a displayed date would leave conflicting commercial records. This
pre-existing demo-data issue is not fixed by this change.
