# Customer and partner QA — September 9, 2026

## Scope and environment

Interactive browser QA started at 11:06 UTC. The staging deployment uses real
WorkOS authentication and the production database, which currently contains only
the FIL One internal account. Customer and partner commerce is not activated
there. Complete commercial journeys were exercised using fictional accounts on
the hosted commerce demo, then repeated locally with the fixes. These are not
claims of real customer purchases, independent legal approval, or provider
activation.

## Findings and fixes

- A newly created customer quote had a next-action label to prepare and issue
  its document, but no control to do so. Its detail now continues the same saved
  quote through document preparation and issuance. The control checks the
  current account, quote identity, version, document binding and issued
  projection before offering order acceptance. Retries reuse command keys; an
  uncertain issue response does not create a replacement draft.
- A past expiry passed the customer form and failed at submission with a generic
  error. Validation now rejects expiry at or before the current time both when
  advancing and when submitting. The input identifies local time.
- Customer and partner forms called draft creation “Review and issue,” and the
  reseller form described its step as a “direct route.” The steps now say
  “Capacity, term, and expiry” and “Review draft.” Introductory text explains
  the customer's next action rather than server identifiers. New copy is
  supplied in all eight supported languages.
- The partner success state sent sellers back to the collection to locate their
  quote. It now links directly to the saved draft. Demo record keys use the
  complete quote identity; the old eight-character UUID timestamp prefix allowed
  multiple quotes to collide.
- Partner quote details showed “Not recorded” for separate prices even when the
  collection showed both amounts. Structured authorized transfer and resale
  amounts now reach the detail. Missing figures are not invented or parsed from
  a combined display string.
- Newly issued demo quotes omitted the generated PDF from their document list.
  The projection now attaches only the rendered document actually bound to that
  quote and account.
- Partner issuance instructions claimed an action would appear automatically,
  but no such control exists. The page now states that channel operations
  prepares the separate documents and links to partner support.

- Referral deal registration saved correctly as pending, but its row was
  hard-coded as resale. The row now describes the requested workload without
  inventing a commercial route, and uses the full identity to avoid the same
  timestamp-prefix collision.

- The packaged preview revealed that an unchanged demo draft became stale after
  five minutes, blocking a buyer returning later. Its projection is now marked
  fresh when rebuilt from the current demo store; production freshness checks
  remain enforced. A one-hour return regression covers this case.

## Verification

- Hosted demo, before fixes: customer empty-offer validation; past-expiry
  failure; successful 25 TB, 12-month USD draft; saved-draft dead end; reseller
  30 TB, 12-month GBP draft with separate transfer/resale amounts; missing-price
  and issuance-handoff defects on its detail.
- Fixed local browser: expired date remains on the terms step; valid draft
  persists; same draft prepares and issues; exact quote reaches order review;
  order form is generated and opens; fictional order creation succeeds.
- 1,855 web unit tests pass across 205 files. New regressions cover expiry
  boundaries, issuance retry/replay, missing authority, changed versions,
  delayed documents, colliding partner references, separated quote prices, and
  document attachment.
- Type checking and production build pass. Final deployment checks and hosted
  verification are recorded in the private launch report.

## Remaining product gaps

Partner quote issuance still needs a complete dual-document workflow; this
change does not pretend to implement one. Production customer onboarding,
partner agreements, commercial inputs and capability activation remain launch
prerequisites. Some seeded demo deadlines are historical. “Create revised draft”
starts another draft rather than a full edit/revision workflow and deserves a
separate pass. The existing full order acceptance flow describes an issued quote
as “accepted” before the final decision; that wording also needs review.
