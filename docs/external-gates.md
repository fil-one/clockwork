# External gates

This is the complete release-candidate register of inputs that require
authority, data, credentials, enrollment, or a decision outside this repository.
Fakes and simulators keep implementation and CI unblocked, but they do not prove
production activation.

Operators execute and record activation evidence using
`docs/operations/external-gate-activation.md`.

`/internal/gates` is the operator-visible projection of this register. Each card
must show owner, current state, last activation-test result, evidence link,
expiry or review date, and affected feature. Visible release states are
`blocked`, `review`, `pending`, `active`, and `not_required`; only a successful
activation test may set `active`. The release-candidate status below remains
non-active until real evidence is attached. Support-feed activation, production
migration, and automated teardown are scoped exceptions noted in severity, not
hidden new-business launch blockers.

No gate may be marked active because an environment variable merely exists.
Activation evidence is append-only, secrets are never displayed, and an expired
credential, policy, approval, or test returns the affected gate to `blocked`.
